## Severity on a hit

Declared severity is what the tables above show. The engine can still change the severity that is scored:

- On a docs, example, sample, demo, or non-core README-like path, prompt and code hits drop one level (`critical` to `high`, `high` to `medium`, `medium` to `low`; `low` and `info` stay). Paths covered are `tests`, `__tests__`, `spec`, `fixtures`, `examples`, `samples`, `docs`, `demo`, `demos`, `testdata`, plus a file whose name starts with `readme`, `changelog`, `contributing`, or `code_of_conduct`. Core instruction files (`SKILL.md`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.cursorrules`, `.windsurfrules`, `.clinerules`, `copilot-instructions.md`, `*.prompt.md`, `*.mdc`) are not downgraded by this path rule.
- On a prose file (`.md`, `.mdx`, `.rst`, `.txt`) that is not already one of those docs paths and is not a core instruction file, code rules whose id starts with `X` or `N` drop one level.
- On a test path (`tests`, `__tests__`, `spec`, `fixtures`, `testdata`, or a `*.test.*` / `*.spec.*` file), code rules whose id starts with `X` drop one further level. The finding note calls that a two-level drop.
- Rules marked `ctx: true` (`X001`, `P001`, `P002`, `P005`, `P009`, `P010`) lower severity when the match is quoted, negated, or discussed in the same sentence. That applies only in instruction files: one level on a core instruction file, two levels otherwise. Code and config files are not treated this way. These drops stack with the path drops above.
- `P011` sets `noEscapeCtx` for Unicode tag characters and bidi overrides, so the path downgrades do not apply to those hits. Tag characters are scored `critical`, bidi overrides `high`, other zero-width characters `medium`, and a BOM-only match `low`. Zero-width and BOM hits can still be downgraded on a docs or test path.
- `X004` and `X012` keep one stored hit per file (`oncePerFile`). Further matches in that file are counted in the snippet and are not extra findings.
- `P012` scores a base64 blob `high` when the decoded text looks like a shell, eval, secret, or instruction payload. Other blobs in instruction files stay `medium`. Other opaque blobs are `low`.
- `D005` stays `medium` for missing frontmatter, `name`, or `description`. A `name` that is not lowercase-hyphen, or a `description` over 1024 characters, is `low`.
- `M002` is `medium` when the latest commit is more than 365 days old, and `low` when it is more than 180 days old. Archived repos skip this rule.
- `A002` stays `high` for `defaultMode: bypassPermissions` and for a VS Code task with `runOn: folderOpen`. Broad `allow` rules, `enableAllProjectMcpServers: true`, and hooks are `medium`.
- `A003` scores a shell `-c` launch and a privileged or host-mounted container `high`. A remote server on plain `http` (other than loopback) is `medium`. An unpinned `npx`, `bunx`, `uvx`, or `pipx` package is `low`.
- `A004` scores an install hook `high` when the script matches curl, wget, a URL, `node -e`, powershell, base64, eval, or `sh -c`. Other `preinstall`, `install`, and `postinstall` hooks are `medium`. `prepare`, `prepublish`, and `prepack` hooks that are not a plain build or `husky` are `low`. A plain build or `husky` on those three hooks is not flagged. Git, URL, file, ssh, or GitHub-shorthand dependencies are `medium`. `*`, `latest`, or an empty range is `low`.
- `A005` scores an extra index or `--trusted-host` `medium`, and an unpinned `git+` requirement `low`.
- `A006` scores event-text script injection and `pull_request_target` plus a checkout of the PR head `high`. `permissions: write-all` is `medium`.

Info findings use a penalty of 0. `N005` is informational and does not change the score.
